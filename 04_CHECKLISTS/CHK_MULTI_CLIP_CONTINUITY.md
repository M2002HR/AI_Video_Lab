# Multi-Clip Continuity Checklist

All required items must pass or be N/A with rationale.

## Master Sequence
- [ ] Total duration and clip count recorded.
- [ ] Clip count is 2/3/4 or deviation is justified.
- [ ] Architecture mode recorded: continuous / hybrid / editorial.
- [ ] Every clip has a distinct role.
- [ ] Overall story arc and final payoff are clear.
- [ ] No clip is filler; four clips are used only when four chapters add value.

## Shared identity
- [ ] Product identity lock is common across clips.
- [ ] Packaging identity is stable.
- [ ] Recurring character identity/count is stable.
- [ ] Scale rules are stable or intentional changes are documented.
- [ ] Shared lighting/style rules or intentional differences are documented.

## Every boundary `Cn -> Cn+1`
- [ ] Previous end state and next start state defined.
- [ ] Transition type recorded.
- [ ] Exact invariants and allowed discontinuities recorded.
- [ ] Product/object/character states are compatible.
- [ ] Camera and movement direction do not contradict.
- [ ] Environment/lighting jump is intentional or absent.
- [ ] Hard-continuity boundaries have approved state evidence.
- [ ] Match/editorial transitions have explicit logic.

## Per clip
- [ ] Normally no more than 1–2 major state changes unless evidence supports more.
- [ ] Simultaneous actions are limited.
- [ ] Start/end state is readable.
- [ ] Final clip reserves enough time for commercial payoff.
- [ ] Minimum sufficient role-clean reference stack is defined.
- [ ] Clip Contract, preflight, baseline Runs, QA, and selected final exist.

## Assembly / sequence QA
- [ ] Trim points and transitions are recorded.
- [ ] Color/exposure and audio/music continuity checked.
- [ ] No unintended repeated action.
- [ ] Total pacing and escalation are coherent.
- [ ] Final hero/payoff is clear.
- [ ] If hard continuity repeatedly fails stochastically, hybrid/match/editorial alternatives were considered.

## Documentation
- [ ] Master Sequence, `sequence_id`, clip IDs, boundary decisions, selected Runs, assembly, and final QA are recoverable from STATUS/HANDOFF/evidence.
- [ ] Important failures/learnings are not chat-only.
