# CHK MULTI-CLIP CONTINUITY

## Gate
همه requiredها باید pass یا N/A مستدل باشند.

## Master sequence
- [ ] total duration و clip count ثبت شده.
- [ ] architecture = continuous / editorial / hybrid ثبت شده.
- [ ] role هر clip روشن است.
- [ ] overall story arc و final payoff روشن است.

## Shared identity
- [ ] product identity lock بین تمام clipها مشترک است.
- [ ] packaging identity ثابت است.
- [ ] character identity/count در صورت recurring بودن ثابت است.
- [ ] scale rule ثابت یا تغییرش مستدل است.
- [ ] lighting/style bible مشترک یا تفاوت intentional ثبت شده است.

## Boundary Cn → Cn+1
- [ ] end state کلیپ قبل تعریف شده.
- [ ] start state کلیپ بعد تعریف شده.
- [ ] transition type ثبت شده.
- [ ] product state سازگار است.
- [ ] object count سازگار است.
- [ ] character count/identity سازگار است.
- [ ] character position در hard-continuity سازگار است.
- [ ] camera direction/orientation contradiction ندارد.
- [ ] movement direction contradiction ندارد.
- [ ] environment/lighting jump ناخواسته ندارد.
- [ ] اگر hard continuity است، boundary reference approved وجود دارد.

## Clip complexity
- [ ] هر clip بیش از 1–2 state change اصلی ندارد مگر evidence خلافش را تأیید کند.
- [ ] actionهای همزمان محدودند.
- [ ] هر clip final readable state دارد.

## Assembly
- [ ] final run هر clip QA شده.
- [ ] trim pointها ثبت شده.
- [ ] transitionها intentional هستند.
- [ ] color/exposure mismatch بررسی شده.
- [ ] audio bridge/music continuity بررسی شده.
- [ ] duplicate/repeated action ناخواسته وجود ندارد.
- [ ] total pacing مناسب است.
- [ ] final commercial hero/payoff واضح است.

## Documentation
- [ ] MASTER_SEQUENCE به‌روز است.
- [ ] clip_id همه Runهای مربوط ثبت شده.
- [ ] boundary decisions ثبت شده.
- [ ] STATUS/HANDOFF final sequence state را منعکس می‌کنند.
- [ ] learning/failure مهم فقط در chat باقی نمانده است.
