# SOP 07 — Scenario Architecture

## Purpose
Execute `STAGE_07` repeatably with traceable evidence and a clear gate.

## Required input
Creative direction + identity + source analysis + tool constraints. Optional inputs may include user feedback, style/scene references, and tool constraints. The previous stage must be approved or have a documented blocker/assumption.

## Procedure
1. Read current `STATUS.md`, this SOP, the relevant checklist, and authoritative evidence.
2. Core stage action: build Process State Map, capacity assessment, duration viability, and adaptive scenario menu without inventing real process.
3. Instantiate the relevant canonical/active prompt when applicable and keep reference roles explicit.
4. Record output, decision, uncertainty, provenance, and failure tags in the stage record or Run.
5. Execute the checklist/gate. Advance `STATUS.md` only after pass or a documented exception; rebuild generated registry views when required.

## Scenario architecture requirements
Before ideation, create a Process State Map and label every process claim as `verified`, `user_confirmed`, `creative_metaphor`, or `unknown`. Assess capacity and duration fit. Generate only genuinely distinct scenario cards; typical candidate ranges are 2–4 for 10s, 3–5 for 20s, 3–5 for 30s, and 2–5 for 40s, but stop whenever new options become superficial variations. Do not enter heavy storyboard/keyframe production before user selection. For multi-clip selection, create a Master Sequence and Clip Contracts, then route to `SOP_MULTI_CLIP_SEQUENCE.md`.

## Output and gate
Expected output: **process state map, capacity assessment, scenario menu**. Pass requires usable output, sufficient provenance, and the stage-specific quality criteria. Fail requires a blocker/failure record and an explicit repair, regenerate, or return-to-root-stage decision.

## AI/tool metadata
The AI task is independent of tool choice. Unknown tool/model/settings are recorded as `unknown`, not guessed. Generations require Run ID, exact prompt, reference roles, settings, output manifest, evaluation, and selection state. Analysis tasks require sources, confidence, and assumptions.

## Escalation
Common root issues include identity drift, ambiguous reference roles, contradictory prompts, and over-complex timelines. Repair local cosmetic errors; regenerate or return to an earlier stage for identity/structural/continuity failures. Repeated failure should produce an OBS/HYP/EXP record rather than endless retries.

## Documentation/language
The Documentation Contract is mandatory. Persist all required text in English only.
